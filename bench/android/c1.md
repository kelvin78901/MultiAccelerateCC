# Task: input hygiene for ASR text, glossary import and SentencePiece parsing

Three independent improvements. Keep every public name below exactly as written.

## A. ASR hallucination and repetition filtering (`AsrTextFilter`)
Whisper-style ASR emits text that was never said. Extend `AsrTextFilter` (package `com.example.myapplication1`):
1. `FilterConfig` gets `filterHallucinations: Boolean = true` and `filterRepetition: Boolean = true`.
2. Hallucinations: when `filterHallucinations` is on, `filter()` returns null for a text that, after lowercasing,
   trimming and removing trailing `.!?…` and surrounding quotes, equals one of: "thank you for watching",
   "thanks for watching", "please subscribe", "subscribe to my channel", "like and subscribe",
   "see you in the next video", "subtitles by the amara.org community", "transcribed by", "[music]", "[applause]",
   "♪", "(music)". Only whole-utterance matches are dropped: "thanks for watching the game with me" is kept.
3. Repetition loops: when `filterRepetition` is on, a run of the same 1–6 word phrase repeated 3 or more times in a
   row (case-insensitive, punctuation between repeats ignored) is collapsed to a single occurrence, keeping the rest
   of the sentence: "I think we should go we should go we should go now" -> "I think we should go now". If the
   whole text is one phrase repeated, the result is that phrase once. Two repeats are left alone.
4. New `fun isHallucination(text: String): Boolean` and `fun collapseRepetitions(text: String): String` on
   `AsrTextFilter` expose the two rules for direct use.
5. Existing behaviour and existing tests in `AsrTextFilterTest` must keep passing.

## B. Glossary file parser (`GlossaryFileParser`)
`GlossaryManager.importUserFile` parses CSV/TSV inline and mishandles quoted fields with commas, extra columns and a
UTF-8 BOM. Move parsing into a new pure-Kotlin `object GlossaryFileParser` in package
`com.example.myapplication1.translation` (no Android or `org.json` imports):
1. `fun parse(text: String): ParseResult` with `data class ParseResult(val entries: List<GlossaryEntry>,
   val rejected: List<Rejected>, val separator: Char)` and `data class Rejected(val line: Int, val reason: String)`
   (`line` is 1-based in the original text, blank lines count). Reuse the existing `GlossaryEntry(en, zh)` type.
2. Strip a leading UTF-8 BOM. Separator: tab if the first non-blank line contains a tab, else comma.
3. RFC 4180 quoting for both separators: fields may be quoted with `"`, a quoted field may contain the separator,
   and `""` inside quotes is a literal quote. Only the first two columns are used; extra columns are ignored.
4. The first non-blank line is a header (skipped, not rejected) when its first field is, case-insensitively, one of
   source, en, english, term, src.
5. Rejected with a reason (and not imported): fewer than two columns ("missing column"), empty source or target
   after trimming ("empty field"), source or target longer than 200 characters ("too long"), any ISO control
   character ("control character"), unterminated quote ("unterminated quote").
6. Duplicate sources (case-insensitive, after trimming): the last one wins in `entries` and each earlier one is
   rejected with reason "duplicate".
7. `GlossaryManager.importUserFile` uses `GlossaryFileParser` and keeps its existing size/encoding checks,
   storage and `ImportResult` contract; when nothing valid is found it still returns the existing error.

## C. SentencePiece parser hardening (`SpmParser`)
`SpmParser.parse` silently stops or returns partial results on malformed input and can overflow on huge lengths.
1. New `fun parseChecked(data: ByteArray): SpmParseResult` with `sealed class SpmParseResult` having
   `data class Ok(val pieces: List<SpmPiece>)` and `data class Malformed(val offset: Int, val reason: String,
   val pieces: List<SpmPiece>)` (pieces successfully read before the error).
2. Malformed cases: a varint longer than 10 bytes, a truncated varint, a length-delimited field whose length is
   negative or runs past the end of the data (or of the enclosing piece), a truncated fixed32/fixed64 field, and an
   unknown wire type (3, 4, 6 or 7). `offset` is the byte offset where the bad field starts.
3. A piece string must be valid UTF-8; invalid bytes make the result `Malformed` with reason "invalid utf-8".
4. `parse()` keeps its signature and returns the pieces read before any error (its current lenient behaviour),
   implemented on top of `parseChecked`.
5. Pieces with no score field get score 0f, with no type field get `TYPE_NORMAL` (as today).
